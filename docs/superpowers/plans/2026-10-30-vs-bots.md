# Engine, Model and Vs Bots Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A playable vs bots mode in the browser: the house-rules engine in TypeScript, the trained model running client side, three bot difficulties, hints with a chess-style evaluation and move labels, sorting, card history, single games and matches.

**Architecture:** A pure TypeScript engine (`web/src/lib/engine`) mirrors the Python engine and is checked against fixtures exported from Python. The model's weights are exported to a binary file served from `web/public/model/`, and a hand-written forward pass (`web/src/lib/model`) runs in a Web Worker. The game screen is a client component driven by a reducer over immutable game states.

**Tech Stack:** Next.js 16.4.3, React 19.3, Tailwind 4, TypeScript, Vitest 5, @dnd-kit/core 6 and @dnd-kit/sortable 10, Python 3.12 with PyTorch for the export scripts.

**Spec:** `docs/superpowers/specs/2026-10-30-web-app-design.md`

This is the first of four plans. Later plans: Best move and game review; vs friends on one device; accounts, stats and vs friends online.

## Global Constraints

- House rules exactly as the Python engine: card = rank * 4 + suit, rank 0 = 3 up to 12 = 2, suits ♦ < ♣ < ♥ < ♠; straights 3-4-5-6-7 < ... < 10-J-Q-K-A < J-Q-K-A-2 < 2-3-4-5-6 < A-2-3-4-5; five-card order straight < flush < full house < four of a kind plus one < straight flush.
- Every game has exactly 4 seats; the holder of the 3♦ opens every game, including each game in a match; the first move must contain the 3♦.
- Only wins are tracked. A match is 3, 5 or 10 games (default 5); most wins takes the match, ties are shared, a match can be ended early.
- No percentages anywhere in the UI.
- Look: paper `#F2F0EA`, ink `#111111`, white cards, accent `#FF5A1F`, red suits `#C8102E`, Archivo and IBM Plex Mono, thick borders and hard shadows (already in `web/src/app/globals.css`).
- Works at 390 px wide and at 1280 px, with touch, mouse and keyboard. Touch targets at least 44 px.
- Copy rules (owner's): no em dashes or en dashes, no timeline references, no cryptic labels.
- Commits: `feat:`, `chore:`, `doc:`, `test:` prefixes, no co-author line.
- Node 20.9+, `python3` for scripts.

## Review Focus

1. **Leading after three passes:** the player whose move was passed by everyone leads, with no pass option. Pinned in Task 3.
2. **A bot or player who runs out mid-trick ends the game immediately;** the remaining moves are not asked for. Pinned in Task 3.
3. **A hand with many five-card options** (for example 7 cards of one suit): legal move generation and scoring stay under 300 ms. Pinned in Task 6.
4. **Manual order survives play:** after playing cards, the remaining cards keep their manual order and a new deal applies the preferred sort. Pinned in Task 9.
5. **Weights fail to load** (offline or a slow network): the game still starts with Easy or Medium bots, and Hard and hints show a clear message instead of hanging. Pinned in Task 7.

### Task 5: Advice: evaluation and labels

**Files:**
- Create: `scripts/advice_cutoffs.py`, `web/src/lib/model/advice.ts`, `web/src/lib/model/advice.test.ts`

**Interfaces:**
- Produces:
  - `winChance(score: number): number` by linear interpolation through these points, measured on 600 self-play games, clamped to [0.01, 0.99] (never shown to users):
    `(-1.0, 0.013) (-0.7, 0.092) (-0.5, 0.188) (-0.3, 0.304) (-0.1, 0.435) (0.1, 0.542) (0.3, 0.614) (0.5, 0.792) (0.8, 0.952)`
  - `evaluation(score: number): number` = `1.5 * (logit(winChance(score)) - logit(0.25))`, rounded to one decimal, clamped to [-9.9, 9.9]. 0 is even; about +0.7 is a small edge; about +6 is close to decided.
  - `type Label = "Best" | "Good" | "Inaccuracy" | "Mistake" | "Blunder"`
  - `labelMoves(scores: Float32Array): Label[]` from the drop in `winChance` against the best move: the top move is Best; drop under 0.02 Good; under 0.05 Inaccuracy; under 0.12 Mistake; otherwise Blunder.
  - `rankAdvice(moves: Card[][], scores: Float32Array): { cards: Card[]; label: Label; evaluation: number | null }[]` sorted best first; `evaluation` only for the top 3 (spec: only the top few options show a number).

- [ ] **Step 1: Write the failing tests:** `evaluation` at score -0.4 (win chance about 0.25) is within 0.2 of 0; `evaluation` increases with score; `labelMoves([0.10, 0.09, 0.0, -0.5])` gives `["Best", "Good", "Mistake", "Blunder"]` (win chance drops 0.005, 0.054, 0.354); ties share Best.
- [ ] **Step 2: Run, see failures. Step 3: Implement. Step 4: Run: PASS.**
- [ ] **Step 5: Check the cut-offs:** `scripts/advice_cutoffs.py` plays 300 games of the model against 3 Smart bots and prints how often the Smart bots' moves get each label. Expected: Blunder under 10%. If not, raise the Blunder cut-off in steps of 0.02 until it is, and record the final cut-offs and frequencies in the design doc's calibration notes.
